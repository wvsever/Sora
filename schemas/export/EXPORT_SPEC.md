# Source export specification

How a customer delivers source data for Sora. Sora never connects to customer databases. The
customer exports files, and the mapping SQL (`sora-tools map`) runs on those files. See
`plans/10_input_model_and_mapping.md`.

## Folder layout

```text
<export>/
├── export_manifest.json          # required: what, when, which reference date (below)
├── source_dictionary.yaml        # required: generated by `sora-tools profile`, then completed by the customer
├── control_totals.csv            # recommended: totals for reconciliation (below)
└── <table>/                      # one folder per source table, any names
    ├── part-0000.parquet         # or .csv
    └── entity_id=<id>/part-0000.parquet   # Hive-style partitions are allowed
```

The reference export (`tests/data/20260630.7z`) follows this layout with `accounting/` and `reference/`
group folders. Grouping folders are allowed.

## File formats

| | Parquet (preferred) | CSV |
|---|---|---|
| Encoding | Native types | UTF-8, header row, `,` separator, `"` quoting, `\n` line ends |
| Amounts | `DECIMAL(p,s)` | `.` decimal separator, no thousands separator, no currency symbols |
| Dates | `DATE` | `YYYY-MM-DD` |
| Booleans | `BOOLEAN` | `true` / `false` |
| Nulls | Parquet nulls | Empty field. No `NULL`, `N/A` or sentinel dates. |
| Column order | Free (matched by name) | Free (matched by name) |

- Files of one table may have different column subsets (union by name). Missing columns are NULL. A consistent column set per table is still preferred.
- One reference date per export. History tables may contain earlier periods.
- File names and partition values must not contain personal data.

## `export_manifest.json`

```json
{
  "institution": "CPPBank NV",
  "reference_date": "2026-06-30",
  "reporting_currency": "EUR",
  "exported_at": "2026-07-15T09:30:00Z",
  "exported_by": "Finance data team",
  "source_systems": ["core banking", "IFRS 9 engine", "collateral management"],
  "tables": ["contract_loan", "counterparty", "..."]
}
```

## Source data dictionary (`source_dictionary.yaml`)

The dictionary is what a mapping author (a person or an AI agent through `sora-mcp`) works from, so it
can be shared even when the data cannot. Generate a skeleton, then complete the empty `description`
fields and the meaning of code values:

```sh
sora-tools profile <export> -o <export>/source_dictionary.yaml [--types-file ...] [--no-codes]
```

```yaml
source: cppbank
tables:
  contract_loan:
    description: One row per loan contract at the reference date.     # completed by the customer
    path: accounting/contract_loan/**/*.csv
    format: csv
    files: 62
    rows: 45611
    columns:
      declared_stage:
        type: string
        description: IFRS 9 stage at the reference date.             # completed by the customer
        null_rate: 0.0
        distinct_approx: 4
        codes: {stage1: "12m ECL", stage2: "lifetime ECL", stage3: "credit-impaired", poci: "POCI"}
```

Rules applied by `profile`:

- Values are listed only for code-like columns: at most 30 distinct values (configurable), each at most 40 characters, not purely numeric.
- Columns whose name suggests personal or free-text data (name, address, IBAN, national code, e-mail, phone, birth, narrative, description, comment, reference, ...) never have values listed.
- `--no-codes` lists no values at all.
- Statistics (null rate, approximate distinct count) are computed locally. Only the YAML file leaves the machine, and only if the customer shares it.

## `control_totals.csv` (recommended)

Totals from the customer's books, used by `sora-tools validate` to reconcile the SIM output.

```csv
entity_id,measure,currency,amount
BANK-CPP-001,gross_carrying_amount_amortised_cost,EUR,12345678901.23
BANK-CPP-001,loss_allowance_stage3,EUR,58015399.48
```

## Minimum content per SIM table

What the source must contain to fill the required SIM columns (full definitions: `schemas/sim/SIM_REFERENCE.md`).

| SIM table | Source content needed |
|---|---|
| `sim_entity` | Legal entities: id, country, functional currency, parent |
| `sim_counterparty` | Obligors: id, country of residence, ESA 2010 sector, natural person flag, NACE (NFCs), SME inputs (turnover, total assets, employees) |
| `sim_exposure` | Contracts: id, entity, obligor, product, currency, IFRS 9 category and stage, gross carrying amount or off-balance nominal, loss allowance/provision |
| `sim_rating` | Ratings per obligor and source (recommended) |
| `sim_collateral`, `sim_collateral_allocation` | Collateral items, values, property country, allocation to contracts |
| `sim_guarantee` | Guarantees received (recommended) |
| `sim_stage_history` | Month-end stage and allowance per contract, ≥ 12 months (≥ 5 years recommended) |
| `sim_credit_event`, `sim_recovery_flow` | Defaults, cures, write-offs, recoveries (for LGD calibration) |
| `sim_fx_rate` | Closing FX rates at the reference date |
