## Notes

- Baseline = the engine before this change (commit e4dea08: std::string dictionaries, string-keyed stage-history sort, single-threaded projection).
- 256MB: DuckDB cannot run the 100x exposure sort/join within 256 MB (it passed once in an earlier ad-hoc run at 1.16 GB peak RSS, so it is borderline); 512 MB is the practical minimum at 100x.
- Peak RSS = engine data (about 0.8 GB at 100x: exposures 56 B, key dictionaries, per-exposure segment and FX) + DuckDB, which uses up to memory_limit for the ORDER BY of sim_exposure and sim_stage_history and some memory outside it.
